# libmarpa-sys Crate (dginev fork)

Low-level FFI bindings to the
[libmarpa](https://jeffreykegler.github.io/Marpa-web-site/libmarpa.html)
C library. The libmarpa 8.6.2 source is bundled as a tarball and
built + statically linked at crate-build time.

The Rust binding file is auto-generated by `bindgen` from
`marpa.h`; this crate's `build.rs` handles tarball extraction,
`./configure && make`, and `bindgen` invocation.

One file is built from a modified copy instead of the tarball's:
`c/marpa_obs.c` raises the default obstack chunk from 4 KiB to 16 KiB and
adds a per-thread cache of freed default-size chunks, so the obstacks libmarpa begins and frees per earleme, recognizer,
bocage, order and value reuse memory instead of calling `malloc`/`free`
(allocation only; parses are unchanged). The cache is a heap struct held by
a pthread key, freed by the key's destructor at thread exit (Windows and
WebAssembly keep plain `malloc`/`free`). A cached chunk is poisoned under
ASan and marked no-access under valgrind (debug-assertion builds where
`<valgrind/memcheck.h>` exists), so a use after free still reports; release
builds compile neither. Its header records the change;
`diff` it against the tarball's `marpa_obs.c` to see it whole. The
test-only `chunk-cache-stats` feature exposes the calling thread's cache
counters (`chunk_cache_stats()`), read by `marpa/tests/obstack_chunk_cache.rs`
(through `marpa-asf`'s feature of the same name) and `tests/obstack.rs`; it adds
counters only, so a stats build takes production's paths.

This is the `[dependencies.libmarpa-sys]` carrier for the
[`marpa`](../marpa/) crate. See the parent workspace `README.md`
for the full picture.
